# HTTPS с самоподписанным сертификатом

## Контекст

Сервис sbom-helper Currently работает по HTTP. Требуется обеспечить шифрование клиент-серверного соединения (HTTPS) для внутреннего сервиса, доступного ограниченному числу пользователей по IP-адресу, без регистрации доменного имени.

**Ограничения:**
- Доступ по IP-адресу (не по имени хоста)
- Внутренний сервис, фильтрация по IP
- Допустимы браузерные предупреждения о самоподписанном сертификате
- Только HTTPS (HTTP не сохраняется)
- Внутренние коммуникации Docker (healthcheck) не должны сломаться

## Решение

Самоподписанный сертификат, генерируемый во время сборки Docker-образа, + SSL-termination на уровне uvicorn.

### Альтернативы, рассмотренные

| Вариант | Плюсы | Минусы | Причина отклонения |
|---------|-------|--------|-------------------|
| nginx reverse proxy | Разделение ответственности | Дополнительный контейнер, сложнее | Избыточно для простого сервиса |
| Caddy reverse proxy | Автогенерация сертификатов | Новая зависимость, менее прозрачно | Не оправдывает добавление |
| mkcert (локальный CA) | Без предупреждений в браузере | Требует установки CA на каждую станцию | Избыточно для допустимых предупреждений |

**Выбран:** Самоподписанный сертификат + uvicorn SSL — самый простой вариант, минимум изменений.

## Архитектура

### Генерация сертификата

Скрипт `scripts/generate-ssl-cert.sh` выполняется во время сборки Docker-образа (оба stage: dev и prod).

**Параметры сертификата:**
- Тип: RSA 2048
- Валидность: 365 дней
- SAN (Subject Alternative Name): `IP:127.0.0.1`, `DNS:localhost`
- Файлы: `/app/ssl/server.key` (приватный ключ), `/app/ssl/server.crt` (сертификат)

Отсутствие внешнего IP в SAN означает, что браузер покажет предупреждение о несовпадении IP-адреса — это приемлемо для данного сервиса.

### Запуск uvicorn

Uvicorn запускается с параметрами SSL:
```
--ssl-keyfile /app/ssl/server.key
--ssl-certfile /app/ssl/server.crt
```

Порт по умолчанию: `8443` (вместо `8000`).

### Healthcheck

Healthcheck внутри Docker-контейнера использует `https://localhost:8443/health` с отключённой верификацией сертификата (через `ssl.CERT_NONE`).

### Локальная разработка

При запуске без Docker (`python -m purl_resolver.main`) SSL подключается опционально через переменные окружения:
```
SSL_KEYFILE=/path/to/server.key
SSL_CERTFILE=/path/to/server.crt
```
Если переменные не заданы — uvicorn работает без SSL.

## Изменения файлов

### Изменяемые

1. **`Dockerfile`** — добавление openssl и SSL-конфигурации в оба stage (dev + prod)
2. **`docker-compose.yml`** — порт 8000 → 8443, healthcheck на HTTPS
3. **`src/purl_resolver/main.py`** — поддержка SSL-параметров через env vars для локальной разработки

### Новые

1. **`scripts/generate-ssl-cert.sh`** — скрипт генерации самоподписанного сертификата

### Не меняются

- Бизнес-логика (резолверы, storage, API)
- Тесты (TestClient не зависит от SSL)
- API-контракт (URL пути не меняются)

## Порядок реализации

1. Создать `scripts/generate-ssl-cert.sh`
2. Изменить `Dockerfile` (оба stage)
3. Изменить `docker-compose.yml` (порт + healthcheck)
4. Изменить `src/purl_resolver/main.py` (опциональный SSL для локальной разработки)
5. Проверить работоспособность (docker compose up, healthcheck, доступ по HTTPS)

## Risks

- **Сертификат истекает через 365 дней** — потребуется ручная регенерация. Для внутреннего сервиса это приемлемо.
- **Браузерное предупреждение** — пользователь должен подтвердить при первом заходе. По условию — допустимо.
- **Нет HTTP fallback** — если SSL-сертификат повреждён, сервис недоступен. Healthcheck это обнаружит.
