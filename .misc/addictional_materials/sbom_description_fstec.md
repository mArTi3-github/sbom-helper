# Приложение № 1

## Форма перечня заимствованных программных компонентов с открытым исходным кодом в машиночитаемом формате

Перечень заимствованных программных компонентов с открытым исходным кодом в машиночитаемом формате представляется в нотации JSON [1] в виде JSON-объекта, содержащего поля, описанные в **Таблице 1**.

### Таблица 1. Требования к полям корневого объекта перечня

| Имя поля       | Тип                 | Описание | Требования к наличию |
|----------------|---------------------|----------|----------------------|
| `bomFormat`    | JSON строка         | Спецификация формата документа. Должно содержать значение «CycloneDX». | Обязательно |
| `specVersion`  | JSON строка         | Версия спецификации документа. Должно содержать значение «1.6». | Обязательно |
| `serialNumber` | JSON строка         | Уникальный серийный номер документа, сгенерированный Разработчиком в соответствии с RFC-4122 [2]. Например, `urn:uuid:3e671687-395b-41f5-a30f-a58921a69b79` | Опционально |
| `version`      | Целое число         | Версия документа. Первоначальное значение — 1. При модификациях должна увеличиваться на 1. | Обязательно |
| `metadata`     | JSON объект         | Дополнительная информация о перечне и продукте. Требования к заполнению полей объекта описаны в таблице 2. | Обязательно |
| `components`   | Массив объектов JSON | Список заимствованных программных компонентов с открытым исходным кодом. Если в продукте используется несколько версий одного и того же компонента, то для каждой версии компонента должна быть отдельная запись. Не допускается объединять в одну запись компоненты, исходный текст которых хранится в нескольких различных репозиториях систем управления версиями. Требования к заполнению полей объектов описаны в таблице 5. | Обязательно при наличии в составе ПО заимствованных компонентов |

### Таблица 2. Требования к полям объекта `metadata`

| Имя поля      | Тип          | Описание | Требования к наличию |
|---------------|--------------|----------|----------------------|
| `timestamp`   | JSON строка  | Дата и время формирования перечня в формате ГОСТ Р 7.0.64-2018 (ИСО 8601:2004). Например, «2022-04-25T09:30:00». | Обязательно |
| `component`   | JSON объект  | Информация о продукте. Требования к заполнению полей объекта описаны в таблице 3. | Обязательно |

### Таблица 3. Требования к полям объекта `component` (информация о продукте)

| Имя поля         | Тип          | Описание | Требования к наличию |
|------------------|--------------|----------|----------------------|
| `type`           | JSON строка  | Описывает тип заимствованного компонента. Допускается использовать следующие значения: `application`, `framework`, `library`, `container`, `platform`, `operating-system`, `device`, `device-driver`, `firmware`, `file`, `machine-learning-model`, `data`, `cryptographic-asset`. Данное поле является обязательным для совместимости со спецификацией CycloneDX, выбор типа компонента осуществляется по усмотрению разработчика. | Обязательно |
| `name`           | JSON строка  | Название продукта. | Обязательно |
| `version`        | JSON строка  | Версия продукта. Длина строки не должна превышать 1024 символа. | Обязательно |
| `manufacturer`   | JSON объект  | Информация об изготовителе продукта. Требования к заполнению полей объекта описаны в таблице 4. | Обязательно |

### Таблица 4. Требования к полям объекта `manufacturer`

| Имя поля | Тип          | Описание | Требования к наличию |
|----------|--------------|----------|----------------------|
| `name`   | JSON строка  | Название организации — изготовителя продукта. | Обязательно |

### Таблица 5. Требования к полям объекта заимствованного компонента (элемент массива `components`)

| Имя поля             | Тип                     | Описание | Требования к наличию |
|----------------------|-------------------------|----------|----------------------|
| `type`               | JSON строка             | Описывает тип заимствованного компонента. Допускается использовать следующие значения: `application`, `framework`, `library`, `container`, `platform`, `operating-system`, `device`, `device-driver`, `firmware`, `file`, `machine-learning-model`, `data`, `cryptographic-asset`. Данное поле является обязательным для совместимости со спецификацией CycloneDX, выбор типа компонента осуществляется по усмотрению разработчика. | Обязательно |
| `name`               | JSON строка             | Наименование компонента. | Обязательно |
| `version`            | JSON строка             | Версия компонента. | Обязательно |
| `purl`               | JSON строка             | Опциональный идентификатор компонента в формате Package URL [3]. | Опционально |
| `externalReferences` | Массив объектов JSON    | Массив объектов, описывающих источник, из которого осуществлялось копирование исходных кодов компонента в собственный репозиторий изготовителя, а также другие внешние по отношению к документу ресурсы: документацию, сайты и т.д. Требования к заполнению полей объектов описаны в таблице 6. Среди элементов массива обязательно должен присутствовать хотя бы один объект с типом `vcs` или `source-distribution`. | Обязательно |
| `properties`         | Массив объектов JSON    | Массив объектов, описывающих свойства компонента. Требования к заполнению полей объектов описаны в таблице 8. Среди элементов массива обязательно должны присутствовать объекты со свойствами `GOST:attack_surface` и `GOST:security_function`. | Обязательно |
| `components`         | Массив объектов JSON    | Список подкомпонентов данного компонента. Допускается перечислять подкомпоненты как в массиве `components` родительского компонента, так и в массиве `components` корневого объекта перечня. Требования к заполнению полей объектов описаны в таблице 5. | Опционально |

### Таблица 6. Требования к полям объекта `externalReferences`

| Имя поля   | Тип                  | Описание | Требования к наличию |
|------------|----------------------|----------|----------------------|
| `type`     | JSON строка          | Описывает тип внешнего ресурса. | Обязательно |
| `url`      | JSON строка          | Если поле `type` имеет значение `vcs`, то в поле `url` помещается унифицированный указатель ресурса URL для репозитория с исходными текстами компонента, из которого осуществлялось копирование исходных кодов (например выполнением команды `git clone`) в собственный репозиторий изготовителя. Если поле `type` имеет значение `source-distribution`, то в поле `url` помещается унифицированный указатель ресурса URL для архива с исходным кодом компонента, который был использован для помещения исходных кодов компонента в собственный репозиторий изготовителя. | Обязательно |
| `hashes`   | Массив объектов JSON | Содержит список хэшей архива с исходным кодом компонента, полученных при помощи различных алгоритмов. Требования к заполнению полей объекта описаны в таблице 7. Если поле `type` имеет значение `source-distribution`, то данное поле является обязательным и среди его элементов обязательно должен присутствовать объект с идентификатором алгоритма `STREEBOG-256` или `STREEBOG-512`. | Опционально (обязательно для `source-distribution`) |

### Таблица 7. Требования к полям объекта `hashes`

| Имя поля    | Тип          | Описание | Требования к наличию |
|-------------|--------------|----------|----------------------|
| `alg`       | JSON строка  | Содержит идентификатор алгоритма, которым был вычислен хэш архива с исходным кодом компонента или другого ресурса. | Обязательно |
| `content`   | JSON строка  | Содержит значение хэш-функции для архива с исходным кодом компонента. Если поле `alg` имеет значение `STREEBOG-256` или `STREEBOG-512`, то поле `content` должно содержать хэш архива с исходными текстами компонента, посчитанный по алгоритму ГОСТ 34.11–2012 с длиной хэш-кода 256 и 512 бит соответственно. | Обязательно |

### Таблица 8. Требования к полям объекта `properties`

| Имя поля   | Тип          | Описание | Требования к наличию |
|------------|--------------|----------|----------------------|
| `name`     | JSON строка  | Название свойства компонента. | Обязательно |
| `value`    | JSON строка  | Значение свойства компонента. Если поле `name` имеет значение `GOST:attack_surface`, то поле `value` должно содержать одно из трёх значений: `yes` — в случае, если подпрограммы (функции) компонента реализуют программный интерфейс, который непосредственно доступен потенциальному нарушителю или входные данные которого потенциальный нарушитель способен гарантированно сформировать определенным образом; `indirect` — в случае, если подпрограммы (функции) компонента реализуют программный интерфейс, на входные данные которого потенциальный нарушитель способен целенаправленно повлиять, но это влияние существенно ограничено теми или иными факторами; `no` — в противном случае. Если поле `name` имеет значение `GOST:security_function`, то поле `value` должно содержать одно из трёх значений: `yes` — если функции компонента непосредственно реализуют функции безопасности средства защиты информации (например, принимают решение по возможности доступа субъекта к объекту; принимают решение о принадлежности анализируемого объекта к классу (например вредоносного ПО, вредоносного трафика); формируют и осуществляют запись сведений о событиях в журнал; управляют функционалом безопасности ядра ОС и процессора, предоставляющим возможности виртуализации и т. п.); `indirect` — если функции компонента участвуют в реализации функций безопасности средства защиты информации, взаимодействуя с компонентами, реализующими функции безопасности средства защиты информации (например, осуществляя различные виды обработки/подготовки данных, выделение структур данных из массива байт, выполнение вычислений над значениями аргументов функции и т. п.), но при этом не принимают непосредственных решений о запуске, остановке, изменении режимов и параметров работы компонентов, реализующих функции безопасности; `no` — если функции компонента не участвуют в реализации функций безопасности средства защиты информации. | Обязательно |

> **Примечание:** В JSON-объектах допускается наличие дополнительных полей, соответствующих спецификации CycloneDX, с информацией, заполняемой по желанию заявителя.

# Приложение № 2

## Пример заполнения перечня заимствованных программных компонентов с открытым исходным кодом в машиночитаемом формате

Ниже приведён корректный пример JSON-документа, соответствующего описанным выше требованиям.

```json
{
  "bomFormat": "CycloneDX",
  "specVersion": "1.6",
  "version": 1,
  "metadata": {
    "timestamp": "2024-04-25T00:00:00",
    "component": {
      "type": "application",
      "name": "Самый лучший межсетевой экран",
      "version": "72.15",
      "manufacturer": {
        "name": "ООО «Ромашка»"
      }
    }
  },
  "components": [
    {
      "type": "library",
      "name": "openssl",
      "version": "3.0.0",
      "externalReferences": [
        {
          "type": "vcs",
          "url": "https://github.com/openssl/openssl/commit/89cd17a"
        }
      ],
      "properties": [
        {
          "name": "GOST:attack_surface",
          "value": "yes"
        },
        {
          "name": "GOST:security_function",
          "value": "yes"
        }
      ]
    },
    {
      "type": "library",
      "name": "requests",
      "version": "2.31.0",
      "externalReferences": [
        {
          "type": "vcs",
          "url": "https://github.com/psf/requests/v2.32.5"
        }
      ],
      "properties": [
        {
          "name": "GOST:attack_surface",
          "value": "yes"
        },
        {
          "name": "GOST:security_function",
          "value": "indirect"
        }
      ]
    },
    {
      "type": "library",
      "name": "extra_rare_packet",
      "version": "0.07",
      "externalReferences": [
        {
          "type": "source-distribution",
          "url": "ftp://178.16.231.54/distribs/extra_rare_packet.tar.gz",
          "hashes": [
            {
              "alg": "STREEBOG-256",
              "content": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
            }
          ]
        }
      ],
      "properties": [
        {
          "name": "GOST:attack_surface",
          "value": "yes"
        },
        {
          "name": "GOST:security_function",
          "value": "no"
        }
      ]
    }
  ]
}
```
