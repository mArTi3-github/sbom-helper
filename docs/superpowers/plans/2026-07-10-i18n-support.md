# i18n / Multilingual Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full bilingual support (English + Russian) to the sbom-helper web UI with language persistence.

**Architecture:** Frontend uses `vue-i18n@9` with `@intlify/unplugin-vue-i18n` for compile-time message compilation. JSON locale files grouped by domain. Backend adds `language` field to existing settings persistence. All API error responses refactored to return machine codes instead of human-readable text; frontend translates via i18n keys.

**Tech Stack:** Vue 3, TypeScript, Vite 8, vue-i18n@9, @intlify/unplugin-vue-i18n, FastAPI, Pydantic

## Global Constraints

- Existing `vue-i18n`-less strings must all be migrated — no hardcoded user-facing strings remain
- `en.json` and `ru.json` must share identical key structure (same keys, different values)
- Language choice survives page refresh (localStorage) and server restart (backend settings field)
- Backend error responses always include `error` field (machine code); `message` field is removed (optional `detail` for technical context)
- Resolver warnings stay in English (not translated)

- [ ] **Step 2: Create i18n/index.ts**

```typescript
// frontend/src/i18n/index.ts
import { createI18n } from 'vue-i18n'
import en from './locales/en.json'
import ru from './locales/ru.json'

export const i18n = createI18n({
  legacy: false,
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en, ru },
})
```

- [ ] **Step 1: Update ApiError class**

The backend may return additional fields alongside `error` (e.g. `max_size_mb`). The `ApiError` must preserve the full response data so frontend error handling can pass it to `t()` for interpolation.

```typescript
// frontend/src/api/client.ts
export class ApiError extends Error {
  status: number
  error: string
  data: Record<string, unknown>
  constructor(status: number, error: string, data: Record<string, unknown> = {}) {
    super(error)  // error code as the Error.message for debugging
    this.name = 'ApiError'
    this.status = status
    this.error = error
    this.data = data
  }
}
```

- [ ] **Step 2: Update apiFetch to handle new format**

Pass the full parsed body as `data`:

```typescript
export async function apiFetch<T>(
  url: string,
  options?: RequestInit,
  format: ResponseFormat = 'json',
): Promise<T> {
  const res = await fetch(url, options)
  if (!res.ok) {
    let errorData: Record<string, unknown> = {}
    try { errorData = await res.json() } catch { /* ignore */ }
    throw new ApiError(
      res.status,
      (errorData.error as string) || 'unknown_error',
      errorData,
    )
  }
  return (format === 'blob' ? res.blob() : res.json()) as Promise<T>
}
```
