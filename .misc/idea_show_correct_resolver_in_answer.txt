Общее описание назначения и структуры текущего проекта sbom-helper доступно в @specs/INDEX.md (и в файлах, на которые есть ссылки в INDEX.md), а исследовать архитектуру проекта можно с помощью mcp-сервера codebase-memory-mcp (название текущего проекта в этом MCP-сервере: "home-administrator-Desktop-projects-sbom-helper"). 
Общие правила работы с проектом описаны в файле @.misc/WORKFLOW.md .
Для планирования, внедрения и тестирования изменений следует использовать методологию, предлагаемую скиллами из набора "superpowers" (если не получается найти нужные скиллы - используй mcp-сервер superpowers-mcp).

Текущая задача состоит в том, что нужно сделать так, чтобы пользователю при успешном нахождении ссылки на исходные тексты в ответе в веб-интерфейсе также возвращалась информация о том, с помощью какого способа была найдена необходимая ссылка (локальная БД или один из рензолверов - purl2repo, ecosyste.ms API или libraries.io API). По сути - нужно указывать в ответе информацию из поля "Resolver" для соответсвующей записи в локальной БД. Но при этом нужно отличать случаи, когда ссылка на исходные тексты была найдена сразу в локальной БД от тех случаев, когда для выполнения поиска ссылки в рамках текущего запроса производился поиск с использованием резолверов. Если ссылка была взята из локальной БД, то в ответе об использованном способе нахождения ссылки должна быть информация в формате "<Значение поля Resolver из лоакльной БД> (local DB)". А если подходящей ссылки не было в локальной БД, но ссылка была обнаружена одним из резолверов, то в ответе об использованном способе нахождения ссылки должна быть информация в формате "<Значение поля Resolver из локальной БД>".
Такая справочная информация нужна как при использовании раздела веб-интерфейса "PURL Resolver" (внутри спойлера "Show details"), так и при использовании раздела  "SBOM Updater" (нужно добавить к возвращаемой пользователю справочной таблице дополнительный столбец "Resolver", содержащий необходимые сведения).
Также в рамках выполнения текущей задачи нужно убедиться, что каждый из резолверов при успешном нахожджении ссылки корректно заполняет поле "Resolver" в локальной БД (указывая на себя).
