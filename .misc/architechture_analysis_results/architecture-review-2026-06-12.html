Problem

~130 строк бизнес-логики (import strategy, fallback defaults, filter construction, pagination) живут в route-обработчиках вместо service layer.

Solution

Извлечь DbAdminService — класс с constructor injection (Storage). Route-обработчики становятся 3-строчными адаптерами.

Benefits

  • leverage — один interface для всех DB admin операций
  • locality — import strategy фиксится в одном месте
  • Тесты перестают требовать TestClient + FastAPI app
  • Устраняется N+1 query pattern в CSV import
  • Устраняется дублирование PurlFilters construction

Problem

Три несовместимых DI pattern: app.state service locator (main.py), parameter bag (service.py), constructor injection (sbom_enrichment.py). resolve_batch — pass-through, ре-пассирующий все 5 параметров без изменений.

Solution

Превратить service.py в класс PurlResolutionService с constructor injection. Унифицировать DI с SbomEnrichmentPipeline. Composition root в main.py создаёт оба класса.

Benefits

  • locality — dependencies declared once, not on every call
  • Единый DI pattern во всём проекте
  • Консистентный composition root
  • Устраняется parameter bag anti-pattern
⚠ Moderate risk: меняет вызывающий код во всех routes и sbom_enrichment.py. Требует координации изменений и временного bridge-слоя для обратной совместимости.

Problem

Два независимых класса с идентичным паттерном: __init__(path), load(), save(), _ensure_parent(), _write(). Дублирование ~40 строк.

Solution

Извлечь generic JsonFileStore[T] с методами load/save/ensure_parent/write. SettingsStore и IgnorePatternsStore наследуют его, добавляя только validation/defaults.

Benefits

  • locality — file I/O logic чинится в одном месте
  • leverage — N stores через один interface
  • Добавление нового JSON store требует ~5 строк
  • Устраняется дублирование json.dumps/read_text/mkdir
⚠ Требует Generic[T] с Pydantic-совместимостью. Validate-логика в load() разная (Pydantic model vs list[dict]), что усложняет единый интерфейс. Два рабочих модуля — риск регрессии при объединении.

Top Recommendation

Extract DB Admin Service — это изменение даёт наибольший выигрыш при наименьшем риске. ~130 строк бизнес-логики живут в route-обработчиках, что:

  • Делает невозможным unit-тестирование import стратегии без HTTP
  • Создаёт N+1 query pattern (один lookup per row при skip_existing)
  • Дублирует PurlFilters construction между list и export
  • Затрудняет добавление новой DB admin функциональности

Изменение чисто механическое: извлечение в отдельный module с constructor injection, routes становятся thin adapters. Zero risk.
