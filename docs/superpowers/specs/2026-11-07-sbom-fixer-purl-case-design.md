# Дизайн: правило `components.lowercase_purl` с двумя режимами в разделе «Исправить SBOM»

Дата: 2026-11-07
Статус: реализовано (2026-11-07)

## 1. Зачем

`sbom-checker.py` проверяет PURL через
`packageurl.PackageURL.validate_string()` и сообщает о символах верхнего
регистра в `namespace`, `name` и `version` для тех типов, у которых
соответствующее поле нечувствительно к регистру. Проверяющие используют этот
скрипт для входного контроля SBOM, поэтому раздел «Исправить SBOM» должен
уметь автоматически приводить такие PURL к каноническому нижнему регистру.

При этом текущая официальная спецификация PURL и определения, на которые
опирается `sbom-checker.py`, расходятся. Например, текущая purl-spec считает
регистрозависимыми `golang` namespace/name, `npm` namespace/name и `gem` name,
а установленный в чекере `packageurl-python 0.17.6` — регистронезависимыми.
Наоборот, для `version` у `pypi`, `oci`, `huggingface` текущая спецификация
требует нижний регистр, а определения чекера помечают version как
регистрозависимую.

Однозначный выбор одного источника истины невозможен: ориентация только на
чекер может испортить регистрозначимые идентификаторы (например,
Go-пути), а ориентация только на purl-spec оставляет часть предупреждений
чекера неисправленными. Поэтому пункт получает два явно переключаемых режима.

## 2. Цели и не-цели

Цели:

- Новый пункт «Привести PURL к строчному регистру» в группе
  «Правки массива components[]».
- Пункт включён по умолчанию.
- Внутри пункта — выбор режима:
  - «В соответствии с требованиями sbom-checker» (по умолчанию);
  - «В соответствии с требованиями purl-spec».
- В справке `(?)` описаны оба режима и перечни типов, к которым применяется
  понижение регистра.
- Правило понижает регистр только разрешённых полей (`namespace`, `name`,
  `version`) в зависимости от типа PURL; `qualifiers`, `subpath` и тип записи
  не переписываются произвольно.
- Правило учитывается в статистике.

Не-цели:

- Не приводим PURL к нижнему регистру целиком: тип-специфичные
  регистрозначимые поля сохраняются.
- Не исправляем ошибку «namespace у `cpan` должен быть в верхнем регистре»:
  правило только понижает регистр, `cpan` namespace не меняется.
- Не меняем `metadata.component` и его поддерево.
- Не удаляем и не добавляем компоненты; за это отвечают правила
  `components.remove_leaf_*`.
- Не добавляем новый код несоответствия в `issues`: правило только
  исправляет и даёт статистику.
- Не трогаем регистр в `qualifiers`, `subpath`, `purl`-типе отдельно и в
  произвольных строковых полях компонента.
- Не синхронизируем автоматически определения чекера и purl-spec между собой:
  это отдельная задача.

## 3. Рассмотренные подходы

### 3.1. Один режим или два

1. **Только режим sbom-checker.** Закрывает все предупреждения проверяющего
   скрипта, но может понизить регистр `golang`/`npm`/`gem`-идентификаторов,
   которые текущая purl-spec считает регистрозначимыми.
2. **Только режим purl-spec.** Безопасен, но оставляет часть предупреждений
   чекера, ради которых пункт и добавляется.
3. **Два режима (выбран).** Пользователь сам выбирает источник истины;
   по умолчанию — `sbom-checker`, потому что именно им проверяют готовые SBOM.
   Минус: усложняется модель опций, UI и справка.

### 3.2. Хранение таблиц типов

1. **Динамические определения чекера + статический снимок purl-spec
   (выбран).** Для режима `sbom-checker` флаги
   `namespace_case_sensitive` / `name_case_sensitive` /
   `version_case_sensitive` читаются из
   `packageurl.validate.DEFINITIONS_BY_TYPE`; недостающие 10 типов
   добавляются из `sbom_utils.py` чекера. Для режима `purl-spec` используется
   статический снимок текущих JSON-определений спецификации. Так режим
   `sbom-checker` следует за установленной версией `packageurl-python`, как и
   сам чекер, а режим `purl-spec` остаётся воспроизводимым снимком.
2. **Обе таблицы статически.** Проще тестировать, но при обновлении чекера или
   спецификации нужны ручные правки.
3. **Вендорить JSON-определения purl-spec и генерировать таблицы.**
   Максимально трассируемо, но избыточно для двух наборов из 13/16/4 и
   36/27/1 типов.

## 4. Поведение правила

### 4.1. Модель опций

```python
class ComponentsFixOptions(BaseModel):
    ...
    lowercase_purl: bool = True
    purl_case_mode: Literal["sbom_checker", "purl_spec"] = "sbom_checker"
```

`components.lowercase_purl` добавляется в `RULE_IDS` после трёх правил
`components.remove_leaf_*` и перед `components.filter_external_references`.
Порядок в `RULE_IDS` задаёт порядок строк статистики и порядок правил в
UI-каталоге. Правило включено по умолчанию.

### 4.2. Семантика режимов

Понижение регистра выполняется по полям `namespace`, `name`, `version`.
Тип PURL берётся из разобранного значения (`PackageURL.type` всегда в нижнем
регистре). `qualifiers` и `subpath` не изменяются по регистру.

**Режим `sbom_checker`.** Повторяет определения типов, на которые опирается
`sbom-checker.py` (`packageurl-python 0.17.6` + 10 типов, добавленных в
`sbom_utils.py`):

- `namespace` понижается у всех типов, кроме `cpan` (там требуется верхний
  регистр), `git`, `huggingface`, `maven`, `swid`, `swift`;
- `name` понижается у всех типов, кроме `cargo`, `cocoapods`, `cpan`, `cran`,
  `git`, `hackage`, `huggingface`, `julia`, `maven`, `nuget`, `opam`, `rpm`,
  `swid`, `swift`, `yocto`;
- `version` понижается только у `vscode-extension`.

У типов с запрещённым или отсутствующим namespace соответствующая операция
фактически не срабатывает, потому что поля нет. `cpan` namespace не
понижается: чекер требует для него верхний регистр. Типы, отсутствующие в
эффективном наборе определений чекера (базовые определения
`packageurl.validate` + 10 добавленных типов из `sbom_utils.py`), не
изменяются.

**Режим `purl_spec`.** Снимок текущих JSON-определений
`docs/types/definitions` официальной спецификации PURL на 2026-11-07
(`case_sensitive: false`; отсутствие поля означает `true`):

- `namespace`: `alpm`, `apk`, `bitbucket`, `brew`, `composer`, `deb`,
  `github`, `hex`, `luarocks`, `qpkg`, `rpm`, `vscode-extension`, `yocto`;
- `name`: `alpm`, `apk`, `bitbucket`, `bitnami`, `brew`, `chrome-extension`,
  `composer`, `deb`, `github`, `hex`, `luarocks`, `oci`, `otp`, `pub`, `pypi`,
  `vscode-extension`;
- `version`: `huggingface`, `oci`, `pypi`, `vscode-extension`.

Остальные типы и неизвестные типы не изменяются. `cpan` namespace не
понижается ни в одном режиме.

### 4.3. Алгоритм

Для каждого компонента в дереве `components[]`:

1. Прочитать `purl`. Если это не непустая строка — пропустить.
2. Разобрать PURL:
   `raw = PackageURL.from_string(purl, normalize_purl=False)`. Этот режим
   сохраняет исходный регистр и процентное кодирование компонентов, но
   корректно разбирает структуру (включая `@scope` у npm, qualifiers/subpath
   и запрещённые namespace). Если разбор завершился `ValueError`, PURL
   считается невалидным и пропускается (его обрабатывает
   `components.remove_leaf_invalid_purl`).
3. По `raw.type` (всегда в нижнем регистре) и выбранному режиму определить,
   какие из полей `namespace`, `name`, `version` разрешено понижать.
4. Для каждого разрешённого поля проверить исходное значение через
   `packageurl.unquote`: если в нём есть символы верхнего регистра
   (`value.lower() != value`), пометить изменение.
5. Если ни одно поле не изменилось — вернуть `None` (компонент не меняется).
6. Иначе собрать новую строку PURL из исходных компонентов:
   - `namespace` (при изменении) — по сегментам: `unquote` → `lower` →
     `quote` → повторное экранирование `/` как `%2F`, сегменты соединяются
     через `/`;
   - `name` (при изменении) — `unquote` → `lower` → `quote` → повторное
     экранирование `/` как `%2F`;
   - `version` (при изменении) — `unquote` → `lower` → `quote` → повторное
     экранирование `/` как `%2F`;
   - неизменённые поля, `qualifiers` и `subpath` копируются из исходной
     строки без перекодирования (суффикс от первого `?` или `#` сохраняется
     дословно).

Используется именно «точечная» пересборка, а не `PackageURL.to_string()`:
`to_string()` повторно применяет глобальные нормализации
`packageurl-python` (например, `_` → `-` для PyPI, нормализацию `pub`,
приведение version у `oci`) и может изменить поля, которые выбранный режим
менять не разрешает. Точечная пересборка гарантирует, что меняются только
поля, разрешённые режимом; `qualifiers` и `subpath` остаются дословно
исходными.

Повторное экранирование `/` как `%2F` обязательно: иначе процентно
закодированный слэш внутри имени, сегмента namespace или version стал бы
структурным разделителем и изменил бы идентичность пакета.

Тип PURL в новой строке берётся из `raw.type`, то есть в нижнем регистре.
Это единственное изменение сверх разрешённых полей: `packageurl-python`
нормализует тип ещё при разборе. Если верхний регистр есть только в типе, а
разрешённые поля уже в нижнем, правило не переписывает строку и тип остаётся
как был.

### 4.4. Область действия

- Обходится всё дерево корневого `components[]`: каждый корневой компонент и
  его вложенные `components`, pre-order.
- `metadata.component` и его поддерево не обходятся — как и у остальных
  правил `components.*`.
- Проприетарные компоненты не исключаются: чекер пропускает их PURL при
  проверке, но понижение регистра для них не вредно и делает SBOM
  каноничнее.
- Компоненты с отсутствующим, `null`, пустым или нестроковым `purl`
  пропускаются.
- Типы, отсутствующие в эффективном наборе определений выбранного режима,
  не изменяются.
- Невалидные PURL пропускаются без изменения.
- Правило не изменяет другие поля компонента.

### 4.5. Место в конвейере

`_apply_components_rules` выполняет:

1. `components.remove_leaf_missing_purl`;
2. `components.remove_leaf_invalid_purl`;
3. `components.remove_leaf_missing_version`;
4. `components.lowercase_purl`;
5. `components.filter_external_references`;
6. `components.filter_properties`;
7. `components.fill_missing_gost_properties`;
8. `components.add_provided_by`.

Понижение регистра выполняется после удаления листьев, чтобы удалённые
компоненты не попадали в статистику, и до остальных правок, чтобы
последующие правила и сбор issues работали с уже каноническим PURL.

### 4.6. Статистика

- `rule_id`: `components.lowercase_purl`.
- `count`: число компонентов, у которых изменилась строка `purl`
  (максимум 1 на компонент, независимо от числа изменённых полей).
- При стандартных настройках появляется ещё одна строка статистики:
  9 статических строк вместо 8.
- При выключенном пункте правило отсутствует в статистике; при включённом, но
  отсутствии подходящих PURL — строка с `count = 0`.

## 5. API и хранение настроек

`GET /api/v1/sbom/fix/options` и `POST /api/v1/sbom/fix/options` работают с
новыми полями автоматически через `SbomFixOptions.model_dump()` и
`SbomFixOptions.model_validate()`. `POST /api/v1/sbom/fix` принимает те же
поля в JSON-строке `options`.

- Файл `./data/sbom_fix_options.json` хранит `lowercase_purl` и
  `purl_case_mode` внутри блока `components`.
- Старый файл без этих ключей получает значения по умолчанию Pydantic:
  правило включено, режим `sbom_checker`.
- Недопустимое значение `purl_case_mode` при сохранении даёт
  `400 invalid_options`; при загрузке повреждённый файл целиком заменяется
  встроенными значениями по умолчанию (существующее поведение стора).
- Миграции и специальной обратной совместимости сверх поведения Pydantic нет.

## 6. UI

### 6.1. Каталог правил и типы

- `frontend/src/types/api.ts`:
  - `ComponentsFixOptions` получает `lowercase_purl: boolean` и
    `purl_case_mode: 'sbom_checker' | 'purl_spec'`;
  - `ComponentsRuleKey = Exclude<keyof ComponentsFixOptions,
    'provided_by_patterns' | 'purl_case_mode'>`.
- `frontend/src/views/sbomFixerRules.ts`:
  - новое правило `components.lowercase_purl` с ключом `lowercase_purl`
    после трёх `remove_leaf_*` и перед `filter_external_references`;
  - пример before/after, который исправляется в обоих режимах:
    `pkg:deb/Ubuntu/OpenSSL@3.0` → `pkg:deb/ubuntu/openssl@3.0`;
  - `ALL_FIX_RULES` включает правило автоматически.

### 6.2. Переключатель режима

Под строкой правила рендерится группа радиокнопок:

```
[✓] Привести PURL к строчному регистру                         (i)
    (•) В соответствии с требованиями sbom-checker
    ( ) В соответствии с требованиями purl-spec
```

- `v-model` — `options.components.purl_case_mode`.
- Обе радиокнопки недоступны, пока `options.components.lowercase_purl`
  выключен.
- Значение режима сохраняется в состоянии и в настройках независимо от
  включённости пункта.
- Атрибуты для тестов: `data-purl-case-mode`,
  `data-purl-case-mode-option="sbom_checker" | "purl_spec"`.
- «Выбрать всё» / «Снять всё» управляют только булевыми правилами и не
  меняют выбранный режим.

  «В соответствии с требованиями purl-spec»;

- Для отображения двух блоков `RuleHelp.vue` получает

## 8. Тесты

Backend (`tests/test_sbom_fixer.py`, `tests/test_sbom_fix_api.py`,
`tests/test_sbom_fix_options_store.py`):

- значения по умолчанию: правило включено, режим `sbom_checker`;
- режим `sbom_checker`:
  - понижает `golang` namespace/name;
  - понижает `gem` name;
  - понижает `npm` namespace и name;
  - понижает все три поля у `vscode-extension`;
  - не меняет `cpan` namespace (верхний регистр сохраняется), `maven`,
    `swift`, `git`;
  - не понижает `version` у `pypi`/`oci`/`huggingface` (version — только
    `vscode-extension`);
  - сохраняет `_` в имени `hackage` и `pypi`, если меняется только регистр;
- режим `purl_spec`:
  - понижает `deb` namespace/name;
  - понижает `pypi` name/version и сохраняет `_`;
  - понижает `oci` name/version;
  - понижает `huggingface` version;
  - не меняет `golang`, `npm`, `gem`, `cpan`;
- общее:
  - вложенные `components[]` обрабатываются, `metadata.component` — нет;
  - отсутствующий/`null`/пустой/нестроковый `purl` пропускается;
  - невалидный PURL пропускается;
  - неизвестный/кастомный тип не меняется в обоих режимах;
  - `qualifiers` и `subpath` сохраняются дословно (включая регистр и
    процентное кодирование);
  - процентно закодированный `/` (`%2F`) в имени, сегменте namespace и
    version сохраняется как `%2F` и не меняет структуру PURL;
  - PURL без version и npm-scope без version разбираются корректно;
  - счётчик и строка статистики;
  - выключенное правило не меняет PURL и отсутствует в статистике;
  - смена режима меняет результат на одном и том же компоненте;

- старый файл настроек без новых ключей получает значения по умолчанию.

## 9. Риски и известные следствия

- Режим `sbom_checker` выбран по умолчанию, поэтому при стандартных
  настройках правило может понизить регистр регистрозначимых идентификаторов
  (`golang`, `npm`, `gem`). Это осознанный выбор: проверяющие используют
  чекер. Пользователь, которому важна безопасность, переключается на
  `purl_spec`.
- Режим `sbom_checker` зависит от установленной версии `packageurl-python`.
  Если в окружении приложения и в окружении чекера окажутся разные версии,
  поведение может разойтись. Минимальная версия поднимается до `0.17.6`;
  при обновлении зависимости режим нужно перепроверить.
- Снимок `purl-spec` статический; при изменении официальной спецификации его
  нужно обновлять вручную отдельной задачей.
- Точечная пересборка меняет только разрешённые поля и сохраняет
  `qualifiers`/`subpath` и неизменённые поля дословно. Тип PURL при
  перезаписи берётся из `raw.type` и поэтому оказывается в нижнем регистре;
  если верхний регистр есть только в типе, строка не переписывается.
  Процентно закодированный `/` (`%2F`) в изменяемом поле сохраняется как
  `%2F` и не превращается в структурный разделитель.
- `cpan` namespace не понижается и не повышается: ошибка «должен быть в
  верхнем регистре» остаётся вне области правила.
- Тип PURL отдельно не исправляется; если верхний регистр есть только в типе,
  строка не переписывается.
- Неизвестные/кастомные типы не изменяются ни в одном режиме: для них нет
  определения, на которое можно опереться, а понижение регистра могло бы
  испортить регистрозначимый идентификатор.
- Проприетарные компоненты обрабатываются, хотя чекер пропускает их PURL.
  Это не создаёт ошибок и делает SBOM каноничнее.
- При переписывании `purl` компонента правило не переписывает корневые
  `dependencies[].ref`: ссылка, точно совпадающая со старым PURL, может стать
  висячей. Переписывание `ref` — отдельная последующая задача.
